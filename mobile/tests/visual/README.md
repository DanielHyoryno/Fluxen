# Visual layout review

This runs the actual Expo web app with intercepted local fixture responses: long device/category names, online/offline meters, telemetry and billing summaries. It does not use a real account. External network requests are blocked.

Start Expo with `EXPO_PUBLIC_API_BASE_URL_WEB=http://localhost:8099/api/v1`, on port 8081. With Playwright and Chromium available, run `node tests/visual/run-review.cjs` from `mobile`. Set `PLAYWRIGHT_MODULE` and `CHROME_EXECUTABLE` if they are installed outside the project. No new mobile dependency is required.

The runner checks English and Indonesian at widths 320, 360, 393 and 430 px. It asserts metric alignment/stacking, navbar position, no page overflow and no runtime errors. It captures Week and Custom states in `mobile/coverage/ui-review/`, which is ignored by Git.

For the long-range Home chart regression, run `node tests/visual/run-home-chart-review.cjs` with the same preview and runtime settings. It simulates 10-, 11-, and 30-day months, with zero and nonzero usage, in both languages at widths 320 and 393 px. It checks Month and Custom modes, chart/track dimensions, ancestor visibility after the entrance animation, page overflow, and scrolling to the last day. Screenshots and `home-chart-results.json` are saved in the same ignored output directory. All data comes from local fixtures.

Additional manual browser checks: Day/Month charts, custom calendar, language switching without resetting the selected period, long device names, Online/Offline badges, device detail, history, billing and profile scrolling. Android system bars and font scaling still require a check on the physical APK; a web viewport does not reproduce Android insets.

For the first-use IoT guide, run `node tests/visual/run-device-tutorial-review.cjs` with the same settings. It checks all six illustrated steps in Indonesian and English at 320×640 and 393×852, visible navigation buttons, scrolling to the Wi-Fi fields, saved dismissal after reload, and reopening from Profile above Logout. It also compares the guide's scan card, typography, selected Manage tab, input dimensions and navbar with the actual Devices screen at the same viewport width. The guide uses the live presentation components in `DeviceSetupPanels`, `HomeDeviceReading`, `MetricGrid` and `TabIcon`; its preview is inert and does not invoke Bluetooth or send configuration. Screenshots and `device-tutorial-results.json` are saved in the same ignored output directory.

For the real token dialog, run `node tests/visual/run-token-dialog-review.cjs`. It creates a meter only in the intercepted local fixtures and checks Indonesian/English at widths 320 and 393 px with synthetic 48- and 96-character tokens. It verifies full-width aligned actions, usable touch targets, token wrapping, screen containment, closing and reopening. Screenshots and `token-dialog-results.json` are saved in the same output directory; no production devices are created.

For interactive daily bars, run `node tests/visual/run-daily-usage-interaction-review.cjs` with the same settings. It selects October 27 on Home and Usage History in both languages, at 320 and 393 px, with zero and nonzero volumes. The fixtures verify that Home shows the sum of both meters while History shows only the selected meter. It also checks period-change selection reset, retained Daily Details, visible readouts after animations, and no page overflow. Results and screenshots are saved in `mobile/coverage/ui-review/`.
